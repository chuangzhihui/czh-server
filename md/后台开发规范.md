## 0. 总则与决策记录

### 0.1 规范来源

本文档的写法来源是**现有代码的成熟约定**（而非理想化设计）：先把团队已经跑通的默契固化成文，再逐步补齐缺失部分。凡是本文没写到的，向下面四条原则对齐：

1. **能用组件库就不用手写** —— antd 有的能力直接用 antd，不自造轮子；
2. **能就近就不集中** —— 样式、类型跟着宿主文件走，不要往全局堆；
3. **能显式就不隐式** —— 类型、宽高、成功判断全部显式写，不依赖默认值与魔法数字；
4. **能一键一眼看懂就不省事** —— 后台是要长期维护的，可读性优先于少写几行。

## 1. 技术栈与工程基线

### 1.1 版本基线

> 下表为**模板基线版本**（2026-10-13 实测 npm `latest` dist-tag 的最新稳定版）。新建工程直接按此安装；存量工程向此迁移的步骤见《改造清单》批次 A。

| 项                                     | 基线版本          | 说明                                                                 |
| ------------------------------------- | ------------- | ------------------------------------------------------------------ |
| **react**                             | **19.3.0**    | 只用函数组件 + Hooks，无 Class 组件                                          |
| **react-dom**                         | **19.3.0**    | 必须与 `react` **同版本号**（peer 要求 `^19.3.0`）                            |
| **antd**                              | **6.6.6**     | 组件库                                                                |
| **@ant-design/icons**                 | **6.x（显式声明）** | antd 6 硬要求 `>= 6.0.0`；**icons 6 与 antd 5 不兼容**。必须写进 `package.json`，不能靠传递依赖 |
| **@ant-design/v5-patch-for-react-19** | **不使用**       | antd 6 原生支持 React 19，禁止安装该补丁                                       |
| `@types/react` / `@types/react-dom`   | 19.3.x        | 与 React 主版本对齐                                                      |
| 语言                                    | TypeScript 5  | `strict: true`；编译目标 `es5`，`noEmit`，仅做类型检查                          |
| 构建                                    | Vite 7.x      | `root: public`，`base: './'`，输出 `../dist`                           |
| 路由                                    | react-router-dom 7.x | `HashRouter`，路由表集中在 `pages/Route/index.tsx`                    |
| 样式                                    | Sass          | 唯一全局入口 `css/main.scss`；布局全站 Flex + 响应式断点；页面/组件私有样式就近同名 `.scss`   |
| 请求                                    | 原生 `fetch`    | 封装在 `util/request.ts` + `isomorphic-fetch`，**不使用 axios**           |
| 富文本 / 存储 / 画布                          | 可选按需引入        | `@wangeditor/editor`、`cos-js-sdk-v5`、`konva` + `react-konva`（引入后需回归三处功能） |

**升级纪律（强制）**：

1. **major 版本升级必须独立分支、独立窗口**，不与业务需求混提（见红线 16）；
2. 升级前必须读完官方 migration 文档，并用官方 CLI 扫描废弃 API，**不能只靠肉眼看文档**；
3. 每完成一步必须 `yarn build` 通过再进入下一步；
4. 升级后必须按 1.2 的通用验收清单逐项过；
5. 升级期间**冻结视觉改动**，避免两套 DOM 结构交叉排查。

### 1.2 依赖升级验收清单（通用）

任何 UI 库 / React 大版本升级，均须过以下清单：

- [ ] `yarn build` 通过，**无 TS 报错、无构建错误**
- [ ] 控制台**无依赖方 deprecation warning**
- [ ] 新版本已废弃的旧补丁包/兼容包**从依赖与代码里彻底移除**
- [ ] 传递依赖改为**显式声明**（凡代码里 import 过的包，必须在 `package.json` 声明）
- [ ] 自定义第三方组件内部样式覆盖**逐个目视复核**（表格 / 弹窗 / 表单 / 菜单 / 页签）
- [ ] 主题切换、暗色、登录页视觉正常
- [ ] 核心通用组件回归：`CZHTable`（虚拟滚动 / 排序 / 分页 / 列宽）、`FormModal`、`CZHSelect`
- [ ] 周边能力回归：上传（COS）、富文本（wangEditor）、画布（konva）、文件库
- [ ] 目标浏览器范围确认
- [ ] 周边包兼容性确认（`antd-img-crop`、`react-konva` 等）

> antd v5 → v6 的**具体迁移步骤与本项目受影响点**，见《改造清单》批次 A。

### 1.3 仓库与副本纪律

**前端代码跟随后端仓库统一管理，一个后端仓库内只有一个前端副本。**

| 项         | 约定                                                      |
| --------- | ------------------------------------------------------- |
| 有效副本      | 后端仓库内的 `czh-admin/`                                     |
| 历史独立仓库    | 一律**归档为只读**，不在其上继续开发（现有两份副本的差异处理见《改造清单》批次 E）            |
| 提交纪律      | 前端改动**只在有效副本提交**，禁止跨副本改同一个文件                            |

### 1.4 环境变量

仅 `VITE_API_URL` 一个变量，在 `.env.development` / `.env.production` 中定义，通过 `import.meta.env.VITE_API_URL` 读取：

**端口对照（以 `application-{profile}.yaml` 实际配置为准）**：

| 环境 | `admin` 端口 | `api` 端口 | 前端 `VITE_API_URL` |
| --- | --- | --- | --- |
| development | **18081** | 8082 | `http://127.0.0.1:18081` |
| test | 8081 | 8081 | 按测试环境域名 |
| production | **18093** | 8081 ⚠️ | 按部署域名 |

- ⚠️ **旧版本文档写的 `8081` 是 `admin` 的 test 环境端口**，dev 实为 **18081**。照抄会导致联调不通（见 §19 坑 1、《服务端开发规范》§20 坑 1）。
- ⚠️ **`api` 的 test 与 prod 同为 8081，互相撞车**（且与 `admin` 的 test 抢占），同一台机器无法同时起两个环境。**新项目初始化时必须改掉**。
- ⚠️ 新增项目若改端口，**必须同时**更新后端 `czh.cors.allowed-origins`，否则登录后的接口会被 OPTIONS 403 拦截（见《服务端开发规范》§20 坑 3）。

### 1.5 构建与目录 root 约定

`vite.config.js` 把 `root` 设为 `public`（即 `index.html` 在 `public/index.html`），构建输出 `../dist` 并递归拷贝 `public` 静态资源。

- **新增静态资源**（字体、第三方 js、不参与构建的图片）放 `public/`；
- **源码一律放 `src/`**；
- `src/static/` 放参与打包的本地图片（默认头像、文件类型图标）。

**页面归属判定（强制）**：

- **模块目录** `pages/system/<模块>/<页面>/`：业务域有**列表页 + 新增/编辑弹窗**（如 `admin/AdminList` + `admin/AddAdmin`、`role/RoleList` + `role/AddRole`）；
- **平铺页面目录** `pages/<页面>/`：独立功能页，无增删改查列表（如 `Login/`）。

两者**不得在同一层级混用**——`pages/system/` 下既有模块目录（`admin/`、`role/`、`menu/`、`set/`）又有平铺页面（`AuthConfig/`、`SetColor/`、`UploadSet/`、`UserInfo/`）是历史遗留，新页面按上述判定二选一，不新增第三种形态。

### 2.1 `api/`：接口与数据模型放进同一个模块目录（**强制**）

**不存在顶层 `models/` 目录。接口和它的数据模型统一放在 `src/api/<模块>/` 下，一个模块一个目录。**

**规则：**

1. **一个模块 = 一个子目录**：`api/admin/`、`api/role/`、`api/menu/` …，目录名用小写模块名；
2. 模块目录内**固定三件套**（一一对应后端 `Controller` / `dto` / `vo`）：

   | 文件           | 放什么                     | 不放什么                |
   | ------------ | ----------------------- | ------------------- |
   | `<模块>Api.ts` | 该模块**全部接口函数**（不写任何类型定义） | 不放 DTO、不放 VO        |
   | `<模块>Dto.ts` | 该模块**全部入参类型**（DTO）      | 不放接口、不放 VO          |
   | `<模块>Vo.ts`  | 该模块**全部返回实体**（VO）       | **不放入参 / DTO**、不放接口 |

   一个模块只此一个接口文件，不按接口拆、不按操作拆；**无入参的模块可只建 Api + Vo**，不留空 Dto 文件；
3. **扩展名统一 `.ts`**（接口与模型文件都不含 JSX），`.tsx` 只用于含 JSX 的组件；
4. Api 文件只 import 类型使用，**不在里面声明 `interface` / `type`**；
5. **接口文件名与目录名保持一致**：`set/` 目录 → `SetApi.ts`；
6. 接口函数命名 `<动作><模块>Api`：`adminListApi` / `addAdminApi` / `delAdminApi`；
7. 每个接口写中文 JSDoc；
8. 返回值必须标注具体 VO 泛型 `httpPost<T>` / `httpGet<T>`；无返回内容用 `void`，**禁止 `any`**；
9. 路径参数拼在 URL 上，表单/查询参数走 `params`；
10. 跨模块通用**入参**（`PageDto`）放 `api/ApiTypes.ts`；通用**返回**包装（`PageInfoVo` / `SelectVo`）放 `api/common/CommonVo.ts`。

> **为什么合并**：接口与它的出入参本是同一件事的两半。分在 `api/` 与 `models/` 两个顶层目录后，改一个字段要在两棵目录树之间来回跳；合并后改接口时 VO 就在隔壁文件，模块边界也一眼可见。

**示例 —— 同一目录 `src/api/admin/` 下的三个文件：**

**① `src/api/admin/AdminApi.ts`（纯接口函数，不声明任何类型）**

```ts
import { httpGet, httpPost } from "../../util/request";
import { AddAdminDto, AdminListDto, EditPwdDto } from "./AdminDto";
import { AdminListVo, GetLoginInfoVo } from "./AdminVo";
import { PageInfoVo } from "../common/CommonVo";

/** 获取登录信息 */
export const getLoginInfoApi = () => {
    return httpPost<GetLoginInfoVo>("/admin/admin/getLoginInfo", {});
}

/** 退出登录 */
export const logoutApi = () => {
    return httpPost<void>("/admin/admin/loginOut", {});
}

/** 修改密码 */
export const editPwdApi = (params: EditPwdDto) => {
    return httpPost<void>("/admin/admin/editPwd", params);
}

/** 管理员列表 */
export const adminListApi = (params: AdminListDto) => {
    return httpPost<PageInfoVo<AdminListVo>>("/admin/admin/adminList", params);
}

/** 冻结/解冻管理员（注意：字段是 adminId，不是 admin_id） */
export const changeAdminStatusApi = (adminId: number) => {
    return httpGet<void>("/admin/admin/changeAdminStatus/" + adminId, {});
}
```

**② `src/api/admin/AdminDto.ts`（只写入参，不带任何逻辑）**

```ts
import { PageDto } from "../ApiTypes";

/** 修改密码入参 */
export interface EditPwdDto {
    oldPwd: string;   // 旧密码
    password: string; // 新密码
}

/** 新增管理员入参 */
export interface AddAdminDto {
    password: string;
    roleId: number;
    userName: string;
}

/** 管理员列表入参 */
export interface AdminListDto extends PageDto {
    /** 昵称 */
    name?: string;
    /** 角色ID */
    roleId?: number;
}
```

### 2.2 `<模块>Dto.ts` 与 `<模块>Vo.ts`：只放类型（**强制**）

**规则：**

1. **`<模块>Dto.ts` 只放入参**，**`<模块>Vo.ts` 只放返回实体（VO）**；两个文件都**不放接口函数**；
2. **与接口文件同目录同模块**：`api/admin/` 下 `AdminApi.ts` + `AdminDto.ts` + `AdminVo.ts` 三件套成对出现；
3. 类型名以 `Vo` / `Dto` 结尾（`AdminListVo`、`EditPwdDto`、`GetLoginInfoVo`）；通用**返回**包装放 `api/common/CommonVo.ts`（`PageInfoVo`、`SelectVo`）；
4. 跨模块通用**入参**（`PageDto`）放 `api/ApiTypes.ts`，**不进任何 Vo 文件**；
5. 字段与后端 VO **同名同义**（小驼峰），带中文注释。

**③ `src/api/admin/AdminVo.ts`**

```ts
/** 登录信息 */
export interface GetLoginInfoVo {
    /** 头像 */
    avatar: string;
    /** 修改密码提示：0 不提示 / 1 警告提示 / 2 强制修改 */
    changePwdType: number;
    /** 权限菜单 */
    menus: AuthMenuVo[];
    /** 系统名称 */
    name: string;
    /** 昵称 */
    username: string;
}

/** 权限菜单 */
export interface AuthMenuVo {
    child?: AuthMenuVo[];
    icon?: string;
    id?: number;
    path?: string;
    title?: string;
}

/** 管理员列表行 */
export interface AdminListVo {
    adminId: number;
    atime: string;
    /** 上次修改密码的时间 */
    lastChangePwdTime: string;
    lastLoginIp: string;
    lastLoginTime: string;
    roleId: number;
    roleName: string;
    /** 是否冻结 */
    status: number;
    userName: string;
}
```

> **提示**：VO 里**不要加 `[property: string]: any` 索引签名**（那是后端代码生成器的产物），加了会绕过类型检查。存量代码此类签名按《改造清单》批次 B 逐步收敛。

### 2.3 分层依赖（单向，禁止反向依赖）

```
pages  →  component  →  util
  ↓           ↓
 api（接口 + DTO + VO 同目录）
```

- **页面不直接写 `fetch`**，必须走 `api/`；
- **`api/` 不感知 UI**，只做参数透传与类型标注；
- **`component/` 不引用 `api/` 的业务接口**（除通用字典类下拉，如 `CZHSelect` 拉角色/管理员列表）。

### 2.4 状态管理：不引入全局状态库（**决策项**）

**状态一律用组件局部 `useState` / `useRef` 管理。**

1. **局部优先**：页面、组件的私有状态放自身 `useState`；父子通信用 props + 回调；
2. **跨层级共享**用 React `Context`（如主题、语言），不要为了共享一个字段就上状态库；
3. **页面间通信**走 URL（路由参数 / query）或后端接口，不用全局内存态；
4. **需要刷新列表**统一调用组件暴露的 `refresh()`（见 7.1），不用全局事件总线或全局变量触发；
5. 少数确实需要跨页面共享的只读数据（如登录信息、系统名）由 `Layout` 拉取后通过 props 下发。

> 若后续出现"多个页面需要读写同一份可变数据"的场景，再单独评审引入方案，**不在本范围**。

## 4. 前后端契约

### 4.1 统一响应 `HttpResponse<T>`

```ts
export interface HttpResponse<T>{
    code: number;   // 状态码
    msg:  string;   // 提示信息
    data: T;        // 数据包
}
```

**三层判据（必读，缺一不可）：**

**① HTTP 状态码层：后端一律返回 200，前端不要看 `res.ok`。**

`request.ts:72` 的 `if (!res.ok) throw new Error('接口请求异常')` 依赖的都是「HTTP 恒 200」这一前提。⚠️ **在后端修复 FE-01 之前，禁止把任何响应改成真 4xx** —— 当前 `catch` 分支既不 `resolve` 也不 `reject`，命中真 4xx 会导致 **Promise 永不 settle、页面永久转圈**。
**本层无例外**，包括后端 `ErrController`（已裁决统一为 HTTP 200 + body code 404）。

**② 业务 code 层（响应体 `code` 字段）——前端唯一判据：**

| code  | 语义                | 前端处理                                                            |
| ----- | ----------------- | --------------------------------------------------------------- |
| `200` | 成功                | 取 `res.data` 渲染                                                 |
| `400` | 参数校验失败 / 业务规则拒绝  | `message.error(res.msg)`，msg 是可读文案                             |
| `401` | 登录失效              | 清 `czhToken` → **跳登录页**                                         |
| `403` | 无权限（**唯一无权限码**）   | `message.error(res.msg)`，不跳转                                    |
| `404` | 请求地址不存在           | `message.error("请求地址不存在")`                                      |
| `500` | 服务异常              | `message.error(res.msg)`（含 traceId 时说明后端兜底了异常，需反馈后端）           |

- **无权限统一为 `403`**：请求层只保留 `403` 分支，禁止 `888` 等自定义码并存；
- **判断成功只允许用 `=== 200`**，禁止 `== 1`、`=== 1`、`=== 888` 等写法（后端从不返回这些值）；
- **`handleCode` 需同步补 `400` / `404` 分支**（现仅处理 401/403）；
- ⚠️ **移除非 2xx 判断（`res.ok`）时，必须同时守卫 `res.json()` 的解析失败**：否则网关 502/504 返回的 HTML 会在 `res.json()` 处抛错并照样掉进 `catch`，**等于把挂起面从「非 2xx」平移到「非 JSON」，没有真正修好**（配合后端 FE-01，见《改造清单》批次 F）。

**③ 错误内容判别层：后端 `/error` 出口不得无差别返回「请求地址不存在」。**

后端 Filter 抛出的业务异常，`@ControllerAdvice` 抓不到（Filter 在 DispatcherServlet 之外执行），会被容器转派 `/error` 后被抹平为 404，**导致真实鉴权失败在日志里显示为「地址不存在」，P0 漏洞的利用尝试在监控中不可见**（后端缺陷 BE-29）。后端 `ErrController` 须读 `RequestDispatcher.ERROR_STATUS_CODE` 与 `ERROR_EXCEPTION` 分类返回。**前端侧只需保证：不把 `404` 当作业务失败展示给用户，也不要把它当爬虫噪音忽略。**

### 4.2 分页

入参 `PageDto`（定义在 `api/ApiTypes.ts`），出参 `PageInfoVo<T>`（定义在 `api/common/CommonVo.ts`）：

```ts
export interface PageDto{ page: number; size: number; orderBy?: string }
export interface PageInfoVo<T>{ list: T[]; total: number }
```

- 排序：`orderBy` 由 `CZHTable` 内部根据表头 sorter 生成（`asc` / `desc`），列表页透传即可，**不要自行拼接排序串**；
- 时间区间：后端约定 `stime` / `etime` 成对出现（见后端规范 6.1），前端筛选区必须同时传或同时不传。

### 4.3 认证

- 登录成功后把 `res.data.token` 写入 `localStorage.czhToken`（键名固定，勿改）；
- 每次请求由 `request.ts` 统一携带请求头 `token`；
- 退出：调 `logoutApi()` + `localStorage.removeItem('czhToken')`。

> **已知取舍**：`localStorage` 存 token 存在 XSS 窃取风险，且无法被服务端主动失效。当前**维持 `localStorage`**；若后续要做"踢下线 / 多端互挤"，再整体评估改为 `sessionStorage` 或 httpOnly Cookie，**不要单个页面偷偷换**。

### 4.4 图形验证码

登录接口需要 `uuid` + `code`：`getCaptchaApi()` 拿 `img`（base64）与 `uuid`，提交时把 `uuid` 合并进表单。验证码**一次性消费**，登录失败必须重新拉取。

## 5. 请求层（`util/request.ts`）

**唯一出口**：`httpPost<T>` / `httpGet<T>` / `httpBlob`（导出/下载）。

```ts
import { httpPost } from "../util/request";
import type { PageInfoVo } from "../api/common/CommonVo";
import type { AdminListDto } from "../api/admin/AdminDto";
import type { AdminListVo } from "../api/admin/AdminVo";

export const adminListApi = (params: AdminListDto) =>
    httpPost<PageInfoVo<AdminListVo>>("/admin/admin/adminList", params);
```

约定：

1. **禁止**在页面/组件里直接 `fetch` 或引入 axios；
2. URL 以 `/` 开头，完整带模块前缀（`/admin/admin/...`、`/admin/setting/...`、`/admin/login/...`）；
3. 单个路径参数走 `httpGet("/admin/admin/delAdmin/" + id, {})`；
4. 文件/导出走 `httpBlob`，它会自动按 `Content-Type` 分流：JSON 按响应体处理、`Blob` 直接返回；
5. 请求层已统一处理 401/403 与网络失败提示，**业务层不要重复弹"网络错误"**；
6. `catch` 里必须给用户反馈，且应由请求层统一兜底；业务层只处理业务分支，**不要把 `err.toString()` 直接弹给用户**。

接口路径前缀对照（后端 `@RequestMapping`）：

| 前缀               | 模块                    |
| ---------------- | --------------------- |
| `/admin/login`   | 登录、验证码、系统名            |
| `/admin/admin`   | 管理员、个人信息、改密、操作日志、登录信息 |
| `/admin/setting` | 参数配置、上传设置、文件库、安全配置    |

| `/admin/backup`  | 数据库备份                 |
| `/admin/common`  | 通用字典（角色下拉、管理员下拉等）     |

## 6. 接口层与数据模型层（`src/api/<模块>/`）

> 目录与文件约定见 **2.1**（目录与 Api 文件）与 **2.2**（Dto / Vo 文件），本章补充**写作规则**。

### 6.1 一句话分工

| 位置                       | 放什么                                 | 不放什么            |
| ------------------------ | ----------------------------------- | --------------- |
| `api/<模块>/<模块>Api.ts`    | 该模块**全部接口函数**（不写类型定义）              | 不放 DTO、不放 VO    |
| `api/<模块>/<模块>Dto.ts`    | 该模块**全部入参类型**（DTO）                  | 不放接口、不放 VO      |
| `api/<模块>/<模块>Vo.ts`     | **只放 VO**（后端返回实体）                   | **不放 DTO / 入参** |
| `api/ApiTypes.ts`        | 跨模块通用**入参**（`PageDto`）              | 不放返回类型          |
| `api/common/CommonVo.ts` | 通用**返回**包装（`PageInfoVo`、`SelectVo`） | 不放入参            |

### 6.2 规则

1. **入参不进 Api / Vo 文件** —— 入参只写在同目录的 `<模块>Dto.ts`；
2. **VO 不进 Api / Dto 文件** —— VO 统一放同目录的 `<模块>Vo.ts`，由 Api import 使用；
3. 类型必须与后端 VO/DTO **字段同名同义**（小驼峰），后端改字段时前端同步改（后端禁止直接返回 Entity，VO 即契约）；
4. 字段写中文注释；
5. **禁止 `any` 泛滥**：`tsconfig` 开了 `strict`，新增代码必须给出具体类型，未知结构用 `unknown` + 断言收敛；**无返回内容的接口用 `void`**；
6. **不要加 `[property: string]: any` 索引签名**；
7. 列表行类型必须传入 `CZHTable<T>` 的泛型，列定义用 `TableColumnsType<XxxVo>` 标注：

```ts
const columns: TableColumnsType<AdminListVo> = [ ... ];
```

## 7. 页面开发范式

### 7.1 页面组件必须 `forwardRef` 并暴露 `refresh`

后台的「刷新」按钮通过 Layout 持有的 `tabRef[id].current.refresh()` 调用当前页签的刷新方法，因此**每个页面组件都必须**：

```tsx
const Index = (_props: any, ref: any) => {
    const tableRef = useRef<CZHTableRef | null>(null);
    const refresh = () => { tableRef.current.onRefresh(); };
    useImperativeHandle(ref, () => ({ refresh }));   // ← 必须
    ...
};
export default forwardRef(Index);
```

### 7.2 列表页标准结构

```
<CZHTableSearch onSearch={...} items={[...]} buttons={[...]} />   // 搜索区
<CZHTable ref={tableRef} columns={columns} onRefresh={onRefresh} auto scroll={{x:'max-content'}} />
```

- 数据加载交给 `CZHTable`：它内部持有 `page / pageSize / orderBy / loading / total`，回调 `onRefresh(pageRequest, callback)`；
- 页面只负责把 `search` 合并进参数并回调结果：

```tsx
const onRefresh = (info: PageDto, callback: (res: HttpResponse<PageInfoVo<AdminListVo>>) => void) => {
    adminListApi({ page: info.page, size: info.size, orderBy: info.orderBy, ...search }).then(callback);
};
```

- 搜索状态变化触发刷新：`useEffect(() => { refresh(); }, [search])`；
- 表格横向滚动 `scroll.x` 优先 `'max-content'`，不要手写像素合计值。

### 7.3 列定义约定

- 每列显式给 `width`、`align: 'center'`；
- 空值统一渲染 `-`（`render: (v: string) => \`${v || '-'}\``）；
- 状态列可点击切换的，必须套 `modal.confirm` 二次确认 + `Tooltip` 说明；
- 操作列用 `.pubbtnbox`（带竖线分隔），文字色取 `theme.useToken().colorPrimary`，**禁止写死 `#1677ff`**。

### 7.4 新增/编辑表单弹窗

统一走 `FormModal.open`（脱离当前 React 树挂载，避免弹窗被页面卸载影响）：

```tsx
FormModal.open({
    title: `添加管理员`,
    width: 360,                       // 360 / 460 / 696 / 900 / 1172 为现有规格档位
    children: <AddAdmin type="add" onOk={() => refresh()} />,
});
```

表单子组件约定：

```tsx
const Index = (props: AddAdminProps, ref: any) => {
    const [form] = Form.useForm();
    const onFinish = (data: any) => {
        props.loading?.(true);               // 交给弹窗的确定按钮 loading
        addAdminApi(data).then(res => {
            if (res.code === 200) {
                message.success(res.msg, 1.2);
                props.close?.();             // 关闭弹窗
                props.onOk?.();              // 通知父页刷新
            } else {
                message.error(res.msg, 1.2);
            }
        }).finally(() => props.loading?.(false));
    };
    useImperativeHandle(ref, () => ({ form }));   // ← 弹窗「确定」会调 form.submit()
    return <Form form={form} onFinish={onFinish} layout="vertical" autoComplete="off"> ... </Form>;
};
export default forwardRef(Index);
```

要点：

- 子组件 `props` 继承 `CommonFormProps`（`loading` / `close`），由 `FormModal` 通过 `cloneElement` 注入，**不要自己实现确定/取消按钮**；
- 新增与编辑**复用同一组件**，用 `type: 'add' | 'edit'` 区分，编辑时把 `data.xId` 合并进提交体；
- 提交成功后顺序：`success 提示 → close → onOk(刷新列表)`。

**FormModal 可配置项（Props 速查）：**

`FormModal.open({ ... })` 的配置项全部列在下面四张表里，**全部可选**，不传即取下表默认值（与 v2.0 之前的行为完全一致）。子组件依旧**不要自己渲染确定/取消按钮**（红线 6）：按钮的增删改一律由**调用方**在 `open` 时通过 props 配置。

*① 关闭行为*

| Props          | 类型        | 默认值              | 说明                                                                    |

| `maskClosable` | `boolean` | 跟随 `closable`    | **是否允许点击遮罩（弹窗外空白区域）关闭**。antd 6 已废弃同名属性、改由 `mask.closable` 承载，组件内已封装，业务侧只写本项 |
| `keyboard`     | `boolean` | 跟随 `closable`    | 是否允许按 Esc 关闭                                                           |

*② 底部按钮*

| `onCancel` | `(ctx) => FormModalAction`    | —   | 点「取消 / × / 遮罩 / Esc」回调；返回 `false` 可阻止关闭      |
| `onClose`  | `() => void`                  | —   | 关闭动画结束后回调（此时弹窗已销毁，适合刷新列表、弹提示）               |

| 字段             | 类型                              | 默认值     | 说明                                                   |
| -------------- | ------------------------------- | ------- | ---------------------------------------------------- |
| `key`          | `string`                        | 必填      | 唯一标识，同时作为 antd `Button` 的 key，也是该按钮 loading 的归属键    |
| `text`         | `ReactNode`                     | 必填      | 按钮文案                                                 |
| `onClick`      | `(ctx) => FormModalAction`      | —       | 点击回调：返回 `false` 阻止后续动作；返回 `Promise` 期间自动接管该按钮 loading |
| `closeOnClick` | `boolean`                       | `false` | 回调放行后是否关闭弹窗                                          |
| `visible`      | `boolean \| () => boolean`      | `true`  | 是否显示，支持函数动态判断                                        |
| `loading`      | `boolean`                       | `false` | 外部控制该按钮 loading                                       |
| 其余             | `ButtonProps`                   | —       | `type` / `danger` / `disabled` / `icon` / `className` 等直接写 |

**回调协议**（`onOk` / `onCancel` / `FormModalButton.onClick` 三者通用）：

```ts
/** 返回 false（或 Promise resolve(false)）＝ 阻止后续动作；返回 Promise ＝ 期间自动 loading */
type FormModalAction = void | boolean | Promise<void | boolean>;

interface FormModalActionContext {
    close: (silent?: boolean) => void;  // 关闭弹窗；silent = true 不触发子组件 cancel 回滚
    submit: () => void;                 // 触发子组件 form.submit()
    setLoading: (e: boolean) => void;   // 设置默认「确定」按钮的 loading
    childRef: React.RefObject<FormModalChildHandle | null>;  // 子组件实例（form / cancel）
}
```

**用法示例：**

```tsx
// ① 禁止点空白关闭（右上角 × 保留）
FormModal.open({
    title: '添加管理员', width: 360, maskClosable: false,
    children: <AddAdmin type="add" onOk={() => refresh()} />,
});

// ② 追加自定义按钮 + 点击回调（异步期间该按钮自动 loading）
FormModal.open({
    title: '添加管理员', width: 360,
    children: <AddAdmin type="add" onOk={() => refresh()} />,
    footerButtons: [
        { key: 'reset', text: '重置', onClick: () => formRef.current?.resetFields() },
        {
            key: 'saveAndAdd', text: '保存并新增', type: 'primary',
            onClick: () => saveDraft(),   // 返回 Promise → 期间 loading；返回 false → 不关弹窗
        },
    ],
});

// ③ 隐藏底部按钮区 / 完全自定义底部
FormModal.open({ title: '预览', footer: false, children: <Preview /> });
FormModal.open({
    title: '主题配置', width: 1172, children: <SetColor />,
    footer: ctx => <Button onClick={ctx.close}>知道了</Button>,
});

// ④ 点「确定」前先做外部校验，不通过就拦住（false → 不提交、不关弹窗）
FormModal.open({
    title: '编辑配置', width: 696,
    children: <AddBasic type="edit" data={item} onOk={refresh} />,
    onOk: async () => ((await checkNameUnique(item.key)) ? undefined : false),
    onCancel: () => confirmDiscard(),      // 返回 false → 取消也不关
});
```

**使用要点（踩坑重灾区）：**

- `footer` **不传**与 `footer={false}` 语义不同：前者走默认「取消 + 确定」，后者隐藏整个底部按钮区；
- `onOk` 是「点确定时」执行、**在 `autoSubmit` 之前**，**不是**「提交成功后」；要完全接管提交请配 `autoSubmit={false}`，自己在回调里请求接口并调 `ctx.close()`；
- 自定义按钮的异步回调**必须 `return` 或 `await` 真实 Promise**：`onClick: () => { save(); }`（没 return）等于同步返回 `undefined`，会被判为放行 → 弹窗立即关闭且没有 loading；
- 默认「确定」只负责 `form.submit()`，**不负责关弹窗**——子组件提交成功后仍需 `props.close?.()`（见上文表单子组件约定）；
- `closable: false` 时 `maskClosable` / `keyboard` / 「取消」按钮默认一起停用；要单独放开某一项就显式覆盖（如 `maskClosable: true`）；
- 回调抛错时组件兜底为「阻止后续动作」并打印错误，避免按钮永久卡 loading；业务异常仍应由回调内部处理（请求层已统一提示，见第 13 章）。

### 7.5 危险操作

删除 / 冻结 / 备份还原等一律 `App.useApp()` 的 `modal.confirm`：

```tsx
modal.confirm({
    title: '警告提示',
    content: '您要删除该项数据吗？删除后将无法恢复！',
    centered: true, maskClosable: true,
    onOk: () => delAdminApi(data.adminId).then(res => {
        if (res.code === 200) refresh(); else message.error(res.msg, 1.2);
    })
});
```

## 9. 路由与菜单

### 9.1 菜单由后端下发

`Layout.tsx` 调 `getLoginInfoApi()` 拿 `menus`（树：`id / title / path / icon / child`），递归转成 antd `Menu` 的 `items`。**前端不写死菜单**，新增页面需在后台「菜单管理」里配 `path`。

### 9.2 新增页面三步（**强制**）

1. **写页面组件**：`pages/system/<模块>/XxxList/index.tsx`（页面一个同名大驼峰目录，内部 `index.tsx` + `index.scss`），导出 `forwardRef`；
2. **注册路由映射**：在 **`src/Route/index.tsx`**（`src` 根级，**不是** `pages/Route/`）的 `Components` 中加一行（key 即后端菜单的 `path`）：

```tsx
export const Components:any = {
    AdminList: lazy(() => import('../system/admin/AdminList')),
    XxxList:   lazy(() => import('../system/xxx/XxxList')),   // ← 新增
};
```

3. **后台配菜单**：菜单管理里新增菜单，`path` 必须与第 2 步的 key **完全一致**（大小写敏感，否则落到 `Page404`）。

> 路由为 `HashRouter`，地址形如 `/#/admin/XxxList`；Layout 会根据 URL 反查菜单、自动生成首个不可关闭的页签。

### 9.3 页签（Tabs）

- 点菜单开新页签、点页签切换、点 × 关闭，全部由 Layout 维护；
- 页面刷新走 Layout 顶栏刷新按钮 → 调当前页签的 `refresh()`（所以 7.1 是强制项）。

## 10. 表单与校验

1. 一律用 antd `Form` + `Form.useForm()`，`autoComplete="off"`（防浏览器填充密码）；
2. 布局：弹窗内用 `layout="vertical"`，搜索区用 `CZHTableSearch` 托管（横向 Row/Col 响应式对象）；
3. 校验规则：
   - 必填 `{ required: true, message: '请输入xxx' }`（文案用「请输入/请选择/请设置 + 字段」，不用「不能为空」）；
   - 复杂校验用 `validator` 返回 `Promise.reject(new Error(msg))`；
   - 通用规则复用 `util/Validator.ts`（手机号、邮箱、正整数、正则合法性、cron）；新规则请加到该文件而不是散落各页面；
4. **密码规则由后端下发**：`getPwdRuleApi()` 返回 `pwdReg` + `pwdRegDesc`，前端用 `Helper.regCheck(pwdReg, value)` 校验并把 `pwdRegDesc` 作为 `extra` 提示，**禁止前端写死密码正则**；
5. 编辑态密码留空表示不修改（`required: type === 'add'`）。

## 11. 主题与视觉（Ant Design 设计令牌）

### 11.1 标准实现

`main.tsx` 读取 `localStorage.themeConfig_honghu`，注入 `ConfigProvider theme={{ token }}`，同时把主色/功能色写成 CSS 变量 `--main-colorPrimary` 等供 SCSS 使用。主题弹窗 `pages/system/SetColor/index.tsx` 提供预设 + 自定义取色。

> 切换主题应通过 `ConfigProvider` **动态更新 token**，**不要 `window.location.reload()`**（会丢失正在填写的表单）。

### 11.2 主题配置推荐方向

按 Ant Design 官方规范组织：

- 预设用**官方 12 主色**（薄暮/火山/日暮/金盏花/柠檬黄/青葱/极光绿/明青/拂晓蓝/极客蓝/酱紫/法式洋红），每套由 seed 自动生成 10 级色板（`colorPrimary` 取第 6 级）；
- 弹窗布局：**左侧组件级实时预览 + 右侧官方主题卡片选择**；
- 保留「自定义 seed」入口，兼容不在官方 12 色内的定制主色。

### 11.3 持久化策略：单机配置（**决策项**）

**主题按「单机配置」处理 —— 只存浏览器本地，不落库、不跟随账号。**

| 项       | 约定                                            |
| ------- | --------------------------------------------- |
| 存储位置    | `localStorage`，键名 `themeConfig_honghu`（固定，勿改）   |
| 生效范围    | **当前浏览器**；换设备、换浏览器、清缓存后回到默认主题                 |
| 是否与账号同步 | **否**（明确不做账号级持久化与服务端下发）                       |
| 默认主题    | `colorPrimary #009B6B`，缺省时由 `main.tsx` 兜底     |

因此**不要**为了"换设备保持主题"去调后端接口或写进个人资料；用户换机后重新选一次是预期行为。默认主题色如需调整，改 `main.tsx` 的兜底对象即可。

### 11.4 视觉规则（**强制**）

1. **禁止写死颜色**：`#333 / #666 / #999 / #f0f0f0 / #1677ff` 这类值在业务组件中一律禁止；需要主色时用：

```tsx
const { token: { colorPrimary } } = theme.useToken();
```

2. 需要在 SCSS 里用主色时用 `var(--main-colorPrimary)`（由 `main.tsx` 注入）；
3. 状态色只用语义令牌：`colorSuccess / colorWarning / colorError`，不要用主色表达成功；
4. 尺寸遵循 antd 官方：**主字体 14 / 行高 22**，圆角 6，控件高度 32；间距取 8 的倍数（4/8/12/16/20/24/32/48）；
5. 中性色用官方透明度体系而非硬编码灰：`rgba(0,0,0,.88) / .65 / .45 / .25`，边框 `#d9d9d9`，分割线 `#f0f0f0`。

## 12. 样式规范

### 12.0 选型决策：用 Sass，**不引入 Tailwind CSS**（**决策项**）

> **保持 Sass，不切换到 Tailwind。** 以下是模板层面的通用理由，具体实测数据见《改造清单》批次 C。

| # | 理由                    | 说明                                                                                                                                                                                  |
| - | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | **收益被 antd 抵消**       | Tailwind 的核心价值是"不用起类名 + 自带间距/色彩约束"。本项目色板、圆角、间距、字号已由 antd **设计令牌**统一约束（见 11 章），布局可直接用 antd `<Flex>` / `<Space>`；约束已经有了，再叠一套等于重复建设。                                                |
| 2 | **第三方组件内部覆盖绕不过去**     | `.ant-tabs-content-holder` 这类是**改组件内部 DOM**，Tailwind 只能写在"自己的元素"上，改不了别人内部的节点。硬要用得写成 `[&_.ant-modal-content]:p-0` 这类任意值选择器，可读性极差。**结果：上了 Tailwind 仍必须保留一个全局 CSS 文件 → 两套体系并存。** |
| 3 | **与 antd 样式优先级冲突**    | antd v5/v6 是 **CSS-in-JS** 运行时注入，Tailwind 是静态 `@layer`。二者叠加必须关掉 preflight 并手工排 layer 顺序，否则会出现"按钮背景被重置、边框样式丢失"一类玄学问题。                                                           |
| 4 | **迁移风险叠加**            | UI 库大版本升级本身就会带来 DOM 结构调整，若同时进行样式体系迁移，等于**两次全量视觉回归叠加**，无法隔离问题。                                                                                                              |
| 5 | **体量不到收益阈值**          | Tailwind 在"上千文件、几十万行样式"的项目收益明显；本模板是**十几页的 CRUD 后台**，迁移成本远大于收益。                                                                                                              |

**真正要治的 4 件事（与 Sass / Tailwind 无关）：**

1. **原子类命名收敛 + 冻结**：新样式不再往全局堆原子类；
2. **内联 `style={{}}` 收回样式文件**；
3. **硬编码色值**换成 antd token 驱动的 CSS 变量，否则主题切换/暗色模式会有漏网点；
4. **布局优先用 antd 组件**：`<Flex>` / `<Space>` 代替手写 flex 类。

**什么时候才该考虑 Tailwind**：全新立项、不依赖 antd 这类重 UI 组件库（或 UI 库本身基于 Tailwind，如 shadcn/ui）、团队接受 HTML 里长 class 串。本模板三条都不满足，故搁置。

### 12.1 样式文件组织：**唯一全局 `main.scss` + 页面/组件就近 `.scss`**（**决策项**）

> **全局样式只有一个文件 —— `src/css/main.scss`。页面或组件需要单独调整样式，就在该页面/组件自己的目录下新建同名 `.scss`，由它自己 import。**

**① 文件清单**

| 类型      | 位置                            | 谁能 import                       | 说明                                      |
| ------- | ----------------------------- | ------------------------------- | --------------------------------------- |
| **全局唯一样式** | `src/css/main.scss`           | **只能由 `main.tsx` import 一次**    | reset + flex 布局骨架 + 响应式工具 + 通用类 + antd 覆盖 |
| 全局辅助文件  | `src/css/_variables.scss`     | 由 `main.scss` `@use`            | 断点 / 间距 / 字体 变量，**不产出 CSS**（下划线开头）      |
| **页面私有样式** | `pages/<模块>/<页面>.scss`        | 仅该页面 `.tsx`                     | 与页面同名：`Login.scss`、`SetColor.scss`、`Layout.scss` |
| **组件私有样式** | `component/<CZHXxx>/index.scss` | 仅该组件 `.tsx`                     | `CZHTable`、`CZHFileComponent` 已是此模式      |

**② 三条判定规则**

1. **判据是"复用次数"**：只在**一处**用到的样式 → **必须**就近写在页面/组件的 `.scss`；被 **3 个以上文件**用到、且 antd 无对应能力的 → 才允许进 `main.scss` 的「通用类」区；
2. **私有样式必须带作用域根类**：`.setColorBox .ltop{...}` 这种以业务根类开头是对的；**禁止在全局文件里出现裸业务选择器**（如直接 `.list .item{...}`）（**作用域完整规则见 12.6**）；
3. **命名与宿主同名**：`Login.scss`、`SetColor.scss`、`CZHTable.scss`；类名用 kebab-case（`.menu-list`），禁用拼音缩写。

**③ 禁止事项**

- **禁止新建第二个全局样式文件**，包括但不限于：`global.css`、`common.css`、`base.scss`、`theme.css`；
- **禁止在 `main.scss` 里堆业务选择器**；
- **禁止引入 Vite / CRA 脚手架的模板样式文件**（`App.css`、`index.css` 之类）：这类模板文件通常带 `#root{max-width:1280px}`、`body{background:#242424}` 等适配 demo 页的规则，**一旦被引会锁死宽度并染黑全站**。新建工程时直接删掉。

### 12.2 全局布局骨架：全站 Flex（**强制**）

项目是**固定侧栏 + 固定顶栏 + 内容区自滚动**的后台外壳，因此布局必须由 Flex 承担，而不是 `height: calc(100vh - xx)` 这类魔法数字。

**① `src/css/main.scss` 骨架**

```scss
@use "./variables" as v;

/* ========== 1. reset ========== */
*, *::before, *::after { box-sizing: border-box; }
html, body, #root { height: 100%; }
body { margin: 0; font-family: v.$font-family; -webkit-font-smoothing: antialiased; }
body::-webkit-scrollbar { display: none; }

/* ========== 2. 布局骨架：全站 flex ========== */
#root { display: flex; flex-direction: column; min-width: 0; min-height: 0; }

.app {                       /* <Layout> 外壳：横向 */
  display: flex;
  height: 100vh;
  min-width: 0; min-height: 0;
}
.app__body {                 /* 右侧：纵向（顶栏 + 内容） */
  display: flex; flex-direction: column;
  flex: 1 1 auto; min-width: 0; min-height: 0;
}
.app__header {               /* 顶栏 90px 固定，不参与压缩 */
  flex: 0 0 90px;
  display: flex; align-items: center; gap: 16px;
  padding: 0 24px;
  background: #fff;
  @include v.down(md) { padding: 0 12px; gap: 12px; }
}
.app__content {              /* Tabs 容器：可滚动而不是被撑开 */
  flex: 1 1 auto;
  display: flex;
  min-width: 0; min-height: 0;
  padding: 8px;
  overflow: hidden;
  @include v.down(md) { padding: 4px; }
}
.app__page {                 /* 单个页面容器 */
  flex: 1 1 auto;
  display: flex; flex-direction: column;
  min-width: 0; min-height: 0;
  overflow: auto;            /* 自己滚，不外溢 */
}
```

**② 骨架 class 与 antd 组件的对应（新增外壳一律照此）**

| antd 元素       | 用哪个 class      | 说明                                    |
| ------------- | -------------- | ------------------------------------- |
| `<Layout>`    | `.app`         | 横向外壳，高度 100vh                         |
| 右侧 `<Layout>` | `.app__body`   | 纵向（顶栏 + 内容）                           |
| `<Header>`    | `.app__header` | 固定 90px，`flex: 0 0 90px`             |
| `<Content>`   | `.app__content` | `flex: 1 1 auto` + `overflow: hidden` |
| 页面根容器         | `.app__page`   | 自滚动容器                                 |

> ⚠️ **禁止 `height: calc(100vh - 90px)` 这类写法**：侧栏折叠、顶栏换行后立刻错位，是最典型的响应式地雷。高度一律交给 flex 链路。

### 12.3 Flex 防压缩三件套（**强制，踩坑重灾区**）

Flex item 的默认行为是 **`min-width: auto` / `min-height: auto`（不能小于内容尺寸）**、**`flex-shrink: 1`（空间不足会被挤扁）**。不显式处理，就会出现"表格撑破容器""侧栏被挤成一条""省略号失效""双滚动条"。

**三条铁律：**

1. **凡参与滚动的容器 → `min-width: 0; min-height: 0;`**（对应主轴方向，缺哪个补哪个）；
2. **凡有固定尺寸、不允许被挤的元素 → `flex: 0 0 auto`（或 `flex-shrink: 0`）**：侧栏、Logo、头像、图标按钮、操作列；
3. **凡需要"吃掉剩余空间"的区域 → `flex: 1 1 auto` + `min-width: 0`**，不要写 `width: 100%`。

**症状对照表（出现这些现象，先查右列）：**

| 症状                       | 根因                            | 修复                                                    |
| ------------------------ | ----------------------------- | ----------------------------------------------------- |
| 内容区被撑高、页面出现**双滚动条**      | flex item 默认 `min-height: auto`，被子内容顶开 | 滚动容器加 `min-height: 0; overflow: auto`                 |
| 侧栏 / 头像 / 图标按钮**被挤扁变形**  | `flex-shrink` 默认 1            | 加 `flex: 0 0 auto`                                    |
| 表格撑破容器、**横向滚动失效**        | 父链某一层没有 `min-width: 0`        | 从 `#root` 到表格父容器**每层**都补 `min-width: 0`；`<Table scroll={{x:'max-content'}}>` |
| 文字**不省略**、反而把布局撑宽        | flex item 不收缩                 | 该列加 `min-width: 0` + 省略三件套                            |
| `margin-left: auto` **顶不到最右** | 父容器不是 flex                | 父级加 `display: flex`                                   |
| 元素**重叠 / 换行错乱**          | 固定 px 宽 + 无换行机制               | 改用 `gap` 代替 margin，必要时 `flex-wrap: wrap`              |

**标准写法（文本省略）：**

```scss
.ellipsis {
  min-width: 0;              // 关键：允许收缩
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

**必查 7 层**：`#root` → `.app` → `.app__body` → `.app__content` → `.app__page` → `CZHTable` 外层 → `.ant-table-wrapper`，**每一层都必须 `min-width: 0`**（缺一层，表格横向滚动就失效）。

### 12.4 响应式布局（**强制**）

**① 断点阈值：与 antd `Grid.useBreakpoint()` 完全一致**（避免 CSS 与 JS 两套判断打架）

| 名称  | 阈值     | 说明                                   |
| --- | ------ | ------------------------------------ |
| `xs` | < 576  | 手机                                   |
| `sm` | ≥ 576  | 大屏手机 / 竖屏平板                          |
| `md` | ≥ 768  | 平板                                   |
| `lg` | ≥ 992  | `<Sider breakpoint="lg">` 在此触发自动折叠   |
| `xl` | ≥ 1200 | 笔电（主用场景）                             |
| `xxl` | ≥ 1600 | 大屏                                   |

`src/css/_variables.scss`：

```scss
@use "sass:map";

$bp: (xs: 0, sm: 576px, md: 768px, lg: 992px, xl: 1200px, xxl: 1600px);

@mixin up($key)   { @media (min-width: map.get($bp, $key)) { @content; } }
@mixin down($key) { @media (max-width: (map.get($bp, $key) - 0.02px)) { @content; } }

$font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'Roboto', 'Helvetica Neue', Arial, sans-serif;
$gap: 8px;
```

**② 四档降级矩阵（新增/改造页面按此实现）**

| 视口                | 侧栏 Sider            | 顶栏 Header         | 内容区留白 | 搜索表单               | 表格                              |
| ----------------- | ------------------- | ----------------- | ----- | ------------------ | ------------------------------- |
| **≥ 1200**（xl，主力） | 展开 **240**          | 全部元素              | 24px  | 一行 4 列（`lg: 6`）    | 全部列                             |
| **992 – 1200**（lg） | 折叠至 **60/80**（图标）   | 全部元素              | 16px  | 一行 3 列（`md: 8`）    | 次要列用 `responsive: ['xl']` 隐藏    |
| **768 – 992**（md） | 自动折叠（`breakpoint="lg"`） | 隐藏用户名文字，保留头像与下拉 | 12px  | 一行 2 列（`sm: 12`）   | 横向滚动 + 操作列 `fixed: 'right'`     |

**③ 实施清单**

1. **栅格一律用 antd `Row` / `Col` 响应式对象**：`<Col xs={24} sm={12} md={8} lg={6}>`；**禁止**手写百分比宽度类（`.item49` / `.item32` / `.row5` 之类）。
2. **布局容器禁止写死业务宽度**：凡 `width: 900px` → 改 `width: 100%; max-width: 900px`。
3. **禁止用 `vh` / `calc(100% - xx)` 定高度**：一律改为 flex 分配 + `min-height: 0`。
4. **表格**：`<Table scroll={{ x: 'max-content' }} />`；列用 `responsive` 控制显隐；**禁止用 `min-width: 1360px` 硬扛横滚**（需要时用 `min-width: max-content`）。
5. **媒体元素**：`img / video / canvas { max-width: 100%; height: auto; }`。
6. **JS 侧判断统一用 `Grid.useBreakpoint()`**，不要在组件里自己写 `window.innerWidth < 768`；CSS 侧用上面的 mixin，二者阈值同源。
7. **验收视口清单**：`1920 / 1440 / 1280 / 992 / 768 / 375` —— 每个新增页面都要在这 6 档目视通过，**不允许出现横向滚动条（表格自身横滚除外）**。

### 12.5 Sass 写法约定

1. **`@use` 取代 `@import`**（Dart Sass 已废弃 `@import`）；变量与断点放 `src/css/_variables.scss`，通过 `@use "./variables" as v;` 引入；
2. **禁止 `@extend`**（跨文件会生成不可控选择器顺序），复用请用 mixin 或直接组合 class；
3. **嵌套不超过 3 层**；**禁止依赖 DOM 结构的末端标签选择器**（`.xxx .flex>p` 一旦改结构就失效）→ 改成语义类名；
4. **`main.scss` 必须分区并写死这 5 个注释锚点**：`① reset`、`② 布局骨架`、`③ 响应式工具`、`④ 通用类（冻结，只减不增）`、`⑤ antd 覆盖（必须带作用域父类）`；
5. **色值禁止硬编码**：token 色走 `theme.useToken()`；`main.tsx` 注入的 CSS 变量（`--main-colorPrimary` / `--main-colorSuccess` / `--main-colorWarning` / `--main-colorError`）可直接在 SCSS 里用 `var()`；中性色用 antd 官方令牌值；
6. **禁止 `!important`**；**禁止裸写 `.ant-btn{...}` 全局污染**，一律带作用域（`.customerModal .ant-modal-content`）；antd v6 起优先用组件的 `styles.*` 插槽而非 CSS 覆盖（**作用域总则见 12.6**）；
7. **滚动条隐藏抽成 mixin**（禁止到处重复写 `::-webkit-scrollbar{display:none}`）：

   ```scss
   @mixin hide-scrollbar { &::-webkit-scrollbar { display: none; } }
   ```

8. **间距一律取 8 的倍数**（4 / 8 / 12 / 16 / 24 / 32 / 48），与 antd 官方模度一致；元素间距优先 `gap`，不要逐个贴 margin 原子类。

> 现有工程的存量样式文件迁移明细，见《改造清单》批次 C。

### 12.6 就近样式的作用域隔离（**强制**）

> **一句话红线**：**除 `src/css/main.scss` 外，任何 `.scss` 的选择器都必须锁在该页面/组件自己的根类之下**；编译产物里**不允许出现任何"没有业务父类"的选择器**。

**① 为什么必须靠约束、而不是靠工具兜底**

项目的就近 `.scss` 是**普通全局样式表**（不是 CSS Modules，项目也未引入）：Vite 编译后每条规则都进入全站文档，**生效顺序由路由 / 懒加载的加载顺序决定**。所以一个裸选择器写下去，等于给全站埋了一颗"看运气"的覆盖雷 —— 表现为「先打开 A 页、再打开 B 页，B 页样式就变了」这类**不可复现的样式漂移**。

**典型实例（本项目实际存在）**：`AddRole/index.scss` 顶层写了 `.flwp{display:grid;grid-template-columns:repeat(2,minmax(0,1fr))}`，而 `CZHFileList/index.tsx` 里 `<div className='flwp uploadlist'>` 用了同名类，`.uploadlist{display:flex}` 与它**同权重（都是 0-1-0）**——谁后加载谁生效。于是「先开过角色编辑弹窗、再开文件库」，文件列表就可能变成两列网格。这类问题**本地难复现、CI 也测不出**，只能靠作用域约束从根上避免。

**② 只允许这三种写法**

| # | 允许的形态                                              | 示例                                                |
| - | -------------------------------------------------- | ------------------------------------------------- |
| 1 | **该页面/组件的根类本身**（BEM block，命名必须带宿主语义）               | `.authSet` / `.uploadSet` / `.CZHTableContainer`  |
| 2 | **根类的自身组合或后代**（`&__el` / `&.active` / `.根类 .ant-xxx`） | `.authSet__grid` / `.setColor__tokens` / `.uploadSet .ant-btn` |
| 3 | **容器类作父类**：容器类由调用方通过 `wrapClassName` / `rootClassName` 传进组件（弹窗/抽屉专用，见 ④） | `.customerModal .ant-modal-body > .ant-form`      |

根类**必须真实存在**于该页面/组件最外层 DOM 上（`<div className='authSet'>`），不能只是 SCSS 里的占位名；一个文件可以有**一到两个**语义明确的根块（如 `Layout/index.scss` 的 `.siderCzh` + `.headerCzh`），但**不允许出现"顺手的泛名类"**。

**③ 明确禁止**

- **禁止裸标签 / 通配选择器**：`p{}`、`div{}`、`li{}`、`*{}`；
- **禁止用泛用类名做顶层选择器**：`.title` / `.item` / `.list` / `.btn` / `.container` / `.flwp` / `.uploadlist` / `.cklist` / `.strip` 这类"看着通用"的名字 —— 它们不是作用域，只是**碰巧还没撞上**；
- **禁止在就近文件里写 `:root` / `html` / `body`**：这些全局锚点只有 `main.scss` 能写；
- **禁止顶层直接写 `.ant-*`**：必须带宿主根类或容器类父类（`.customerModal .ant-modal-content` ✅ / `.ant-modal-content` ❌）；
- **禁止 `@keyframes` / `@font-face` / 自定义 CSS 变量用泛名**（`fade` / `--primary`）：一律带宿主前缀（`authSet-fade` / `--authSet-primary`），避免与别处同名互覆；
- **禁止跨宿主复用类名**：A 页的类名不许出现在 B 页的 `.scss` 里，哪怕只是"想顺手覆盖一下"。

**④ 弹窗 / 抽屉类组件的特例（最容易踩）**

`.open()` 系列弹窗与抽屉是 `createRoot` 到 `body` 的（**不在页面 DOM 内**），此时页面根类**包不住它**，作用域根必须自己挂上去：`<Modal wrapClassName='customerModal'>` / `<Drawer rootClassName='xxxDrawer'>`，SCSS 里再以它作父类。`CZHModal/index.scss` 就是标准答案：

```scss
/* ✅ 容器类由组件通过 wrapClassName 挂到 modal 根上，作用域成立 */
.ant-modal-wrap.customerModal .ant-modal-body > .ant-form { padding: 20px 24px 4px; }
```

**⑤ 正反例对照**

```scss
/* ❌ 反面：全是裸顶层选择器 —— 谁用同名类谁中招，且随加载顺序变化 */
.flwp { display: flex; }
.title { font-weight: 600; }
p { margin: 0; }
.ant-modal-content { padding: 0; }

/* ✅ 正面：全部锁在宿主根类下 */
.uploadSet {                                  /* 对应页面最外层 <div className='uploadSet'> */
  display: flex;
  flex-direction: column;

  &__grid { display: grid; gap: 16px; }       /* BEM 元素 */
  &__card { flex: 1 1 auto; min-width: 0; }
  .ant-modal-content { padding: 0; }          /* 仅命中本页内的弹窗 */
}
```

**⑥ 自检方法（两条，各 10 秒）**

1）**静态**：列出所有就近 `.scss` 的顶层选择器 —— 除根类外不应再出现别的：

```bash
cd czh-admin
for f in $(find src -name "*.scss" ! -name "main.scss" ! -name "_*"); do
  echo "--- $f"; grep -nE '^[^ \t/@$}][^{]*\{' "$f"
done
```

2）**动态（最可靠）**：打开 A 页 → 切到 B 页 → **切回 A 页**，A 页样式必须完全一致；再 `FormModal.open` 一个弹窗并关掉，列表页样式必须不变。**出现任何变化即为跨页副作用**，回头用第 1 条定位。

> 存量 `.scss` 的作用域收敛清单（哪些文件、哪些选择器、按什么顺序改）落在《现有后台改造清单》**批次 C-5**。本节**对新代码立即生效**（提交前自检项见 17.3、红线 21）；存量按**"改哪收哪"**逐步收敛，不强制一次性返工。

5. `console.log` 仅用于临时排查，**提交前必须清除**。

## 18. 团队红线速查（前端）

1. **不直接 `fetch`**，所有请求走 `api/` + `util/request.ts`。
2. **字段一律小驼峰**，禁止 `role_id` / `admin_id` 这类下划线写法。
3. **成功判断只允许 `res.code === 200`**（`== 1` / `=== 1` / `=== 888` 一律清掉）；**无权限只认 `403`**。
4. **页面组件必须 `forwardRef` 并暴露 `refresh`**，否则顶栏刷新按钮报错。
5. **新增页面必须注册进 `src/Route/index.tsx` 的 `Components`**（`src` 根级，**不是** `pages/Route/`），key 与后台菜单 path 一致。
6. **表单弹窗一律用 `FormModal.open`**，子组件 `useImperativeHandle` 暴露 `form`，不自建确定/取消按钮；**需要改关闭行为、增删底部按钮或接按钮回调时，一律走 `FormModal` 的 props（见 7.4），不要手写 footer 绕开组件**。
7. **禁止写死颜色**，主色取 `theme.useToken().colorPrimary`；主题只在本地 `localStorage` 单机生效，不调接口。
8. **危险操作必须二次确认**（`modal.confirm`），成功后 `close → onOk → refresh`。
9. **密码规则取后端 `pwdReg`**，不写死正则。
10. **不引入全局状态库**，状态用局部 `useState`；跨页面通信走 URL 或接口。
11. **提交前清 `console.log`**，禁止新增 `any`、禁止 `!important`、禁止裸覆盖 `.ant-*` 全局样式。
12. **枚举/字典下拉走 `CZHSelect`**，不在页面里重复请求。
13. **禁止 `dangerouslySetInnerHTML`** 渲染后端数据；不在前端存储/展示密钥类敏感信息。
14. **一个后端仓库只维护一个前端副本**，不在历史归档副本里开发。
15. **接口与数据模型同目录、三件套分离**：`<模块>Api.ts`（纯接口）+ `<模块>Dto.ts`（入参）+ `<模块>Vo.ts`（VO）；**不存在 `models/` 目录**，Api 里不写类型定义、Vo 里不写入参（见 2.1 / 2.2）。
16. **依赖升级只走独立分支独立提交**（尤其 UI 库 major），不与业务需求混提；升级后必须过 1.2 验收清单。
17. **样式用 Sass，不引入 Tailwind**；不新增全局原子类、不新增静态内联 `style={{}}`、不写硬编码色值（见 12.0、12.5）。
18. **全局样式只有一个入口 `src/css/main.scss`**；页面/组件要改样式就在自己目录建**同名 `.scss`** 就近引用，**禁止新建第二个全局样式文件、禁止往全局里堆业务选择器**（见 12.1）。
19. **Flex 必须写防压缩三件套**：滚动容器 `min-width: 0` / `min-height: 0`，不允许被挤的元素 `flex-shrink: 0`，剩余空间用 `flex: 1 1 auto`（见 12.3）。
20. **页面必须响应式**：栅格用 antd `Row`/`Col` 响应式对象，**禁止写死容器宽度、`vh`/`calc` 魔法高度、`min-width` 硬扛横滚**；断点阈值统一用 antd 一套（576/768/992/1200/1600），新增页面须过 6 档视口（见 12.4）。
21. **就近 `.scss` 必须自锁作用域**：**除 `main.scss` 外**，文件里的顶层选择器只能是对应页面/组件的**根类**（或由 `wrapClassName` / `rootClassName` 挂上的容器类），**禁止裸标签、泛用类名、无父类的 `.ant-*` 外溢** —— 就近 `.scss` 是全局样式表，一个裸选择器就是一次跨页副作用（见 12.6）。
22. **新增/改动 `util/` 与 `component/CZH*` 必须补单测**，`yarn test` 通过；覆盖率基线只增不减（见 17.4）。
23. **路由注册位置唯一**：`src/Route/index.tsx`（`src` 根级），`pages/` 下不得再建 `Route` 目录（见 9.2）。
24. **分支判断只看响应体 `code`，禁止依赖 HTTP 状态码 `res.ok`**：后端恒返 200（后端 FE-01 修复前改真 4xx 会导致 Promise 永不 settle、页面永久转圈）。无权限码唯一为 `403`。⚠️ **移除非 2xx 判断（`res.ok`）时，必须同时守卫 `res.json()` 的解析失败** —— 否则网关 502 返回的 HTML 会在 `res.json()` 处抛错照样掉进 catch，等于把挂起面从「非 2xx」平移到「非 JSON」，没有真正修好（见 4.1）。
25. **`404` 只表示「请求地址不存在」**：任何业务失败（含鉴权失败、token 过期）都不得复用 404 表达，否则会被监控当爬虫噪音过滤（见 4.1 ③；后端 BE-29）。

## 19. 经验总结与避坑（前端）

> 从历次联调、返工、样式漂移中沉淀的前端侧教训，与《服务端开发规范》§20 配套。
> 每条坑都给出**症状 / 根因 / 排查**三段，遇到同类问题先对号入座。

### 坑 4：筛选静默失效 / 按钮传 undefined（字段命名不一致）

- **症状**：搜索条件传了但后端不收；点按钮传参 undefined，TS 却不报错。
- **根因**：数据库字段是下划线（`role_id`），后端 VO 转小驼峰（`roleId`），前端误写下划线字段；若类型带了索引签名（`[key: string]: any`），TS 不会报错。
- **排查**：`grep -rn "_[a-z]" src/api/ --include="*.ts"`，VO/DTO 里不应出现下划线字段；对照后端 VO 源码逐字段核对，不看接口文档猜。

### 坑 5：点了按钮没反应（code 判据错误）

- **症状**：操作实际成功，但提示不弹、列表不刷新。
- **根因**：历史代码里写 `res.code == 1` 判成功 —— 后端成功码是 `200`，条件永不命中，静默吞掉整个回调。
- **排查**：全项目只允许 `res.code === 200`；`grep -rn "code == 1\|code === 1\|code == 888\|code === 888" src/` 必须为空（红线 3）。

### 坑 6：页面样式随机变化（裸选择器跨页污染）

- **症状**：同一页面样式时好时坏，且与用户访问顺序相关；本地难复现。
- **根因**：就近 `.scss` 是**普通全局样式表**，生效顺序随路由懒加载变化；顶层裸选择器（如 `.flwp`）与他处同名类同权重互抢（实例见 12.6 ①）。
- **排查**：`yarn lint:scope` 扫顶层选择器白名单；动态回归 A→B→A 切换后样式必须一致。根治办法只有一个：选择器锁宿主根类（12.6）。

### 坑 7：清 Modal 内边距不生效（覆盖目标错了）

- **症状**：给 `.ant-modal-content` 写 `padding: 0` 没反应。
- **根因**：antd 6 的 padding 挂在 `.ant-modal-container` 上，不是 v5 时代的 `.ant-modal-content`。
- **排查**：DevTools 里逐层看 padding 实际挂在哪个节点，再写带宿主父类的覆盖（`.customerModal .ant-modal-container { padding: 0; }`）。升级 UI 库 major 后，**不要沿用旧版 DOM 结构的覆盖选择器**。

### 坑 8：弹窗里换主题无效（createRoot 独立上下文）

- **症状**：页面切主题后，弹窗/抽屉里组件仍是旧配色。
- **根因**：`FormModal.open` 等静态方法用独立 `createRoot` 挂载到 `body`，拿不到页面树的 ConfigProvider / ThemeContext。
- **排查**：静态弹窗必须用 `wrap` 包装注入上下文（读取当前主题 token 后再渲染）；**禁止在静态弹窗里直接用 `theme.useToken()` 并期望它跟随页面**。

### 坑 9：URL 无限拼接（navigate 相对路径）

- **症状**：连续点几次菜单后地址栏变成 `/system/admin/system/admin/...`，页面 404。
- **根因**：`navigate('system/admin')` 相对路径在当前路由上叠加。
- **排查**：**路由跳转一律写绝对路径**（`navigate('/system/admin')`）；code review 看到 `navigate(` 参数不带 `/` 开头一律打回。

### 坑 10：改完样式零变化（死文件）

- **症状**：`.scss` 改了，构建成功，页面毫无变化。
- **根因**：该 `.scss` 文件从未被 `import`（重构/改名后遗留的死文件）。
- **排查**：反向核对 —— 对目标文件 `grep -rn "<文件名>" src/`，确认存在 import；顺手清掉无人引用的样式死文件。

### 前端性能红线（5 条）

1. 页面级一律 `React.lazy` + `Suspense` 分包（路由与 `Components` 映射全面 lazy），新增页面照此注册；
2. 表格默认开 `virtual` 虚拟滚动（`CZHTable` 已内置），列多给 `scroll.x`；
3. 表格高度由 `CZHTable` 内部监听 resize 算 `scrollY`，外部禁止再套固定高度；
4. 字典类下拉由 `CZHSelect` 内部拉取，页面不得重复请求同一字典；
5. Flex 链必查 7 层祖先的 `min-width: 0` / `min-height: 0`（防压缩三件套，见 12.3 与红线 19）。
